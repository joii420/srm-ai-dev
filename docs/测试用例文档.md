## 一、用户认证模块

### TC-AUTH-001 正常登录

| 项 | 内容 |
|----|------|
| 优先级 | P0 |
| 前置条件 | 数据库中存在用户 `dev01`，密码 `Test@1234`，角色 `developer` |
| 测试步骤 | 1. 访问平台首页<br>2. 在登录页输入账号 `dev01`，密码 `Test@1234`<br>3. 点击「登录」按钮 |
| 预期结果 | 1. `POST /auth/login` 返回 200，body 包含 `token` 和 `userInfo`<br>2. `token` 存入 localStorage<br>3. 页面跳转至 Page 签出页<br>4. 后续请求 Header 携带 `Authorization: Bearer <token>` |

### TC-AUTH-002 账号或密码错误

| 项 | 内容 |
|----|------|
| 优先级 | P0 |
| 前置条件 | 同 TC-AUTH-001 |
| 测试步骤 | 1. 输入正确账号 `dev01`，错误密码 `wrong123`<br>2. 点击「登录」 |
| 预期结果 | 1. 返回 401，提示「账号或密码错误」<br>2. 不跳转，停留在登录页<br>3. localStorage 中无 token |

### TC-AUTH-003 空账号/空密码提交

| 项 | 内容 |
|----|------|
| 优先级 | P1 |
| 前置条件 | 无 |
| 测试步骤 | 1. 不输入账号和密码，直接点击「登录」<br>2. 只输入账号不输入密码，点击「登录」<br>3. 只输入密码不输入账号，点击「登录」 |
| 预期结果 | 1. 表单校验不通过，提示必填项<br>2. 不发送请求 |

### TC-AUTH-004 Token 过期自动跳转

| 项 | 内容 |
|----|------|
| 优先级 | P0 |
| 前置条件 | 用户已登录，系统配置 JWT 有效期为 8h |
| 测试步骤 | 1. 登录成功后，手动修改 localStorage 中 token 为过期 token<br>2. 发起任意后端请求（如 GET /pages） |
| 预期结果 | 1. 后端返回 401<br>2. 前端清除 localStorage 中的 token<br>3. 自动跳转至登录页 |

### TC-AUTH-005 未登录访问受保护页面

| 项 | 内容 |
|----|------|
| 优先级 | P0 |
| 前置条件 | 未登录状态（localStorage 无 token） |
| 测试步骤 | 1. 直接访问 IDE 工作区 URL<br>2. 直接访问依赖库管理页 URL<br>3. 直接访问系统配置页 URL |
| 预期结果 | 所有页面均重定向至登录页 |

### TC-AUTH-006 获取当前用户信息

| 项 | 内容 |
|----|------|
| 优先级 | P1 |
| 前置条件 | 用户已登录 |
| 测试步骤 | 调用 `GET /auth/me` |
| 预期结果 | 返回当前用户 userId、username、displayName、role |

### TC-AUTH-007 登出

| 项 | 内容 |
|----|------|
| 优先级 | P1 |
| 前置条件 | 用户已登录 |
| 测试步骤 | 1. 点击用户头像或登出按钮<br>2. 调用 `POST /auth/logout` |
| 预期结果 | 1. 返回 200<br>2. 前端清除 localStorage token<br>3. 跳转至登录页<br>4. 使用旧 token 再请求返回 401 |

## 二、用户管理模块（管理员）

### TC-USER-001 管理员创建用户

| 项 | 内容 |
|----|------|
| 优先级 | P0 |
| 前置条件 | 以管理员账号登录 |
| 测试步骤 | 1. 调用 `POST /auth/users`，body: `{ username: "newdev", password: "Pass@1234", role: "developer", displayName: "新开发者" }` |
| 预期结果 | 1. 返回 201，包含新用户信息<br>2. 密码以 bcrypt 哈希存储，数据库中无明文<br>3. 新用户可用创建的账号密码登录 |

### TC-USER-002 普通开发者无权创建用户

| 项 | 内容 |
|----|------|
| 优先级 | P0 |
| 前置条件 | 以 developer 角色登录 |
| 测试步骤 | 调用 `POST /auth/users` |
| 预期结果 | 返回 403 Forbidden |

### TC-USER-003 管理员重置用户密码

| 项 | 内容 |
|----|------|
| 优先级 | P1 |
| 前置条件 | 以管理员账号登录，存在目标用户 |
| 测试步骤 | 调用 `PUT /auth/users/:id/password`，body: `{ password: "NewPass@5678" }` |
| 预期结果 | 1. 返回 200<br>2. 目标用户使用新密码可登录<br>3. 旧密码不可用 |

### TC-USER-004 管理员删除用户

| 项 | 内容 |
|----|------|
| 优先级 | P1 |
| 前置条件 | 以管理员账号登录，存在目标用户且该用户无活跃签出 |
| 测试步骤 | 调用 `DELETE /auth/users/:id` |
| 预期结果 | 1. 返回 200<br>2. 该用户无法再登录<br>3. 用户列表中不再显示 |

### TC-USER-005 创建重复用户名

| 项 | 内容 |
|----|------|
| 优先级 | P1 |
| 前置条件 | 数据库已存在用户 `dev01` |
| 测试步骤 | 调用 `POST /auth/users`，username 设为 `dev01` |
| 预期结果 | 返回 409 或 400，提示用户名已存在 |

## 三、Page 签出/签入模块

### TC-CHECKOUT-001 正常签出 Page

| 项 | 内容 |
|----|------|
| 优先级 | P0 |
| 前置条件 | 用户已登录；目标 Page（DashboardPage）状态为「空闲」；SSH Key 已配置且连接测试通过 |
| 测试步骤 | 1. 进入 Page 签出页<br>2. 选择 DashboardPage 卡片<br>3. 点击「签出并进入 IDE」 |
| 预期结果 | 1. 显示签出步骤动画（锁定 → 创建容器 → git clone → 依赖库加载 → AI 启动 → 健康检查）<br>2. checkouts 表新增一条记录，status='active'，user_id 为当前用户<br>3. Docker 容器创建成功，SSH Key 注入 tmpfs<br>4. git clone -b dev 从 GitLab 成功拉取代码至 /workspace/<br>5. 依赖库拉取至 /deps/<br>6. /api/health 返回 200<br>7. 页面跳转至 IDE 工作区<br>8. 文件树展示 DashboardPage 目录结构（canvas.json、JsObjects/） |

### TC-CHECKOUT-002 签出已被他人签出的 Page

| 项 | 内容 |
|----|------|
| 优先级 | P0 |
| 前置条件 | DashboardPage 已被用户 A 签出 |
| 测试步骤 | 用户 B 尝试签出 DashboardPage |
| 预期结果 | 1. Page 卡片显示「已签出」状态和签出人<br>2. 签出按钮禁用或不可点击<br>3. 后端返回 409 或 423，提示该 Page 已被签出 |

### TC-CHECKOUT-003 正常签入 Page

| 项 | 内容 |
|----|------|
| 优先级 | P0 |
| 前置条件 | 用户已签出 DashboardPage，且在 IDE 中做了代码修改 |
| 测试步骤 | 1. 在 IDE 工作区点击「签入」按钮<br>2. 输入 commit message（可选） |
| 预期结果 | 1. 容器执行 git add . && git commit && git push origin dev<br>2. 代码成功推送至 GitLab DashboardPage 仓库 dev 分支<br>3. Docker 容器被停止并删除<br>4. checkouts 表记录 status 更新为 'checkedin'，checked_in_at 填充<br>5. Page 状态恢复为「空闲」<br>6. 前端跳回 Page 签出页 |

### TC-CHECKOUT-004 签出超时（>60s）自动回滚

| 项 | 内容 |
|----|------|
| 优先级 | P0 |
| 前置条件 | 模拟容器启动超时场景（如 GitLab 网络延迟） |
| 测试步骤 | 签出一个 Page，使健康检查超过 60s 未通过 |
| 预期结果 | 1. 步骤动画显示超时提示<br>2. 容器被自动停止并清理<br>3. tmpfs 中的 SSH Key 随容器销毁<br>4. Page 签出锁解除，状态恢复「空闲」<br>5. 提示用户重试 |

### TC-CHECKOUT-005 git clone 失败回滚

|----|------|
| 优先级 | P0 |
| 前置条件 | SSH Key 配置错误或 GitLab 仓库不存在 |
| 测试步骤 | 签出一个 Page |
| 预期结果 | 1. git clone 报错<br>2. 容器回滚销毁<br>3. Page 锁解除<br>4. 提示用户检查 SSH Key 配置或 GitLab 连通性 |

### TC-CHECKOUT-006 git push 失败（签入失败）

| 项 | 内容 |

### TC-CHECKOUT-007 Page 列表状态展示

| 项 | 内容 |
|----|------|
| 优先级 | P0 |
