# Skill 用户手册

## 什么是 Skill

Skill 是预设的 AI 指令模板。当你在 IDE 中与 AI 对话时，激活一个 Skill，AI 就会按照该 Skill 定义的规则和要求来回答你的问题、生成代码或审查代码。

简单理解：**Skill = 告诉 AI "你应该怎么做" 的一套规则**。

---

## 快速开始

### 第一步：签出程序

在程序列表中选择一个程序，点击"签出"进入 IDE 工作区。签出过程中系统会自动将所有已启用的 Skill 注入到你的开发容器中。

### 第二步：打开 AI 对话

在 IDE 工作区右下角找到 AI Chat 面板，点击展开。

### 第三步：选择 Skill

在聊天输入框上方，你会看到可用的 Skill 列表。点击勾选你需要的 Skill，可以同时选择多个。

### 第四步：发送消息

输入你的问题或需求，发送消息。AI 会结合你选中的 Skill 指令来回复。

**示例：**

```
选中 Skill：[代码审查助手]
输入消息：帮我检查一下 JSObject1.js 的代码质量

→ AI 会按照"代码审查助手"中定义的审查规则，逐项检查你的代码并给出改进建议
```

## 使用场景示例

### 场景一：按规范写代码

```
选中：[编码规范]
消息：帮我写一个用户列表查询函数

→ AI 生成的代码会自动遵循团队的命名规范、错误处理规范等
```

### 场景二：代码审查

```
选中：[代码审查助手]
消息：审查当前文件

→ AI 按照预设的检查清单逐项审查，输出格式统一的审查报告
```

### 场景三：生成测试用例

```
选中：[单元测试生成器]
消息：为 calculateTotal 函数生成测试用例

→ AI 按照团队的测试框架和规范生成测试代码

### 场景四：组合使用

```

## 常见问题

### Q：我看不到任何 Skill？

Skill 需要管理员在后台配置并启用。如果列表为空，请联系管理员添加 Skill。

### Q：签出后新增了 Skill，我需要重新签出吗？

是的。Skill 在签出时注入到容器中，签出后新增或修改的 Skill 需要重新签出才会生效。

### Q：Skill 会影响所有对话吗？

不会。Skill 只在你主动勾选后才会生效。不勾选任何 Skill 时，AI 按默认方式回答。每次对话可以选择不同的 Skill 组合。

### Q：可以同时激活多个 Skill 吗？

可以。多个 Skill 的提示词会同时注入，AI 会综合所有激活 Skill 的规则来回答。建议选择互补的 Skill，避免规则冲突。

### Q：Skill 的使用次数是什么？

系统会自动统计每个 Skill 被使用的次数。使用次数高的 Skill 会排在列表前面，方便快速找到常用的 Skill。同一次对话中重复使用同一个 Skill 只计数一次。

## 管理员指南

> 以下内容面向 admin 角色用户。

### 进入管理页面

登录后，在左侧导航栏点击 "⚡ Skill 管理"。

### 创建 Skill

1. 点击 "新建技能"
2. 填写基本信息：

| 项目 | 示例 | 说明 |
|------|------|------|
| 名称 | 代码审查助手 | 唯一标识，用户在列表中看到的名字 |
| 图标 | 🔍 | 一个 emoji，显示在名称前面 |
| 分类 | 代码质量 | 便于归类管理 |
| 描述 | 按照团队规范审查代码 | 帮助用户了解这个 Skill 的用途 |

3. 编写提示词：

```
你是一个代码审查专家。请按照以下规则审查代码：

1. 命名规范：变量使用 camelCase
2. 错误处理：异步操作必须有 try-catch
3. 安全性：禁止拼接 SQL

发现问题后按以下格式输出：
- 等级：🔴严重 / 🟡警告 / 🔵建议
- 位置：文件名:行号
- 描述：问题说明
- 建议：如何修复
```

4. 点击保存

### 编辑 Skill

在技能卡片上点击编辑按钮，修改名称、提示词、字段等信息后保存。

### 启用 / 禁用

- 点击技能卡片上的开关切换启用状态
- 禁用的 Skill 不会注入到新签出的容器中
- 已签出的容器中的 Skill 不受影响（需重新签出）

### 版本管理

修改提示词前建议先创建版本快照：

1. 点击技能详情中的 "创建版本"
2. 系统自动保存当前提示词和字段的完整快照
3. 版本号自动递增（v1.0 → v2.0 → v3.0）

如果修改后效果不理想：

1. 在版本列表中找到之前的版本
2. 点击 "回滚"
3. 提示词和字段恢复到该版本的状态

### 提示词编写技巧

**1. 明确角色**

```
你是一个 [角色描述]。
```

**2. 列出规则**

```
## 规则
1. 具体规则一
2. 具体规则二
```

**3. 定义输出格式**

```
## 输出格式
请按以下格式输出：
- 标题
- 内容
- 建议
```

**4. 给出示例（效果最好）**

```
## 示例
输入：function getData() { ... }
输出：
- 🟡 函数名不够语义化，建议改为 fetchUserList
- 🔴 缺少错误处理，建议添加 try-catch
```

**5. 使用模板变量**

在提示词中使用 `{{变量名}}` 定义占位符，然后添加对应的字段定义。用户使用时系统会弹出输入框让用户填写。

```
请用 {{language}} 语言重写以下代码：
{{code}}
```

### 好的 Skill 示例

#### 接口文档生成器

```
名称：接口文档生成器
图标：📝
提示词：
你是一个 API 文档专家。请为用户指定的函数或接口生成规范的接口文档。

文档格式要求：
1. 接口名称和描述
2. 请求方式和路径
3. 请求参数表格（参数名、类型、必填、说明）
4. 响应结构（含成功和失败示例）
5. 调用示例
```

#### 性能优化建议

```
名称：性能优化建议
图标：🚀
提示词：
你是一个前端性能优化专家。分析用户提供的代码，给出性能优化建议。

关注点：
1. 不必要的重复计算
2. 大数据量循环优化
3. 异步操作并行化
4. 缓存策略

输出要求：
- 当前问题描述
- 优化方案
- 优化前后对比代码
- 预期性能提升说明
```
