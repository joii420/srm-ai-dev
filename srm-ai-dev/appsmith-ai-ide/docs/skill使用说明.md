# Skill 使用说明

## 1. 功能概述

Skill（技能）是一套可配置的 AI 提示词模板系统。管理员可以预定义一组结构化的提示词，开发者在 IDE 中使用 AI 对话时选择激活相应的 Skill，AI 将按照 Skill 中定义的提示词指令进行工作。

**核心价值**：将团队的开发规范、编码模式、最佳实践等沉淀为可复用的 AI 提示词模板，统一团队 AI 辅助开发的质量和一致性。

---

## 2. 应用场景

| 场景 | 示例 |
|------|------|
| 代码规范 | 定义代码风格规则，AI 生成代码时自动遵循团队规范 |
| 代码审查 | 定义审查清单，AI 按照检查项逐一审查代码 |
| 单元测试 | 定义测试编写规范，AI 自动生成符合规范的测试用例 |
| 重构指导 | 定义重构策略模板，AI 按照模式进行代码重构 |
| 文档生成 | 定义文档格式模板，AI 按照格式生成接口/组件文档 |
| 业务逻辑 | 定义特定业务领域的处理规则，AI 按照业务规范开发 |

---

## 3. 数据模型

### 3.1 Skill（技能）

| 字段 | 类型 | 说明 |
|------|------|------|
| name | String | 技能名称（唯一） |
| description | Text | 技能描述 |
| icon | String | 图标（Unicode emoji），默认 "⚡" |
| category | String | 分类标签 |
| prompt | Text | **提示词模板**，支持 `{{fieldName}}` 占位符 |
| keywords | JSON | 关键词数组，用于搜索发现 |
| tags | JSON | 标签数组 |
| enabled | Boolean | 是否启用，默认 true |
| version | String | 版本号，默认 "v1.0" |
| callCount | Integer | 使用次数统计 |

### 3.2 SkillField（技能字段）

每个 Skill 可以定义多个输入字段，用于填充提示词模板中的占位符。

| 字段 | 类型 | 说明 |
|------|------|------|
| fieldId | String | 字段标识（如 "user_input"） |
| label | String | 显示标签 |
| type | String | 字段类型：text / textarea / select / number |
| required | Boolean | 是否必填 |
| placeholder | Text | 输入框占位提示 |
| options | JSON | 下拉选项数组（仅 select 类型） |
| token | String | 模板占位符，如 `{{fieldName}}`，对应 prompt 中的变量 |
| sortOrder | Integer | 显示排序 |

### 3.3 SkillVersion（版本快照）

| 字段 | 类型 | 说明 |
|------|------|------|
| version | String | 版本标签（v1.0, v2.0, ...） |
| promptSnapshot | Text | 该版本的完整提示词快照 |
| fieldsSnapshot | JSON | 该版本的字段定义快照 |
| modifiedBy | FK(User) | 操作人 |

## 4. 管理配置

### 4.1 访问入口

管理员登录后，在左侧导航栏点击 "⚡ Skill 管理" 进入技能管理页面。

> 仅 admin 角色可以创建、编辑、删除技能。

### 4.2 创建技能

1. 进入 Skill 管理页面
2. 点击 "新建技能"
3. 填写基本信息：

```
名称：代码审查助手
图标：🔍
分类：代码质量
描述：按照团队编码规范审查代码，检查潜在问题并给出改进建议
标签：review, quality
```

4. 编写提示词模板：

```
你是一个代码审查专家。请按照以下规范审查用户提交的代码：

## 审查规则
1. 检查命名规范：变量使用 camelCase，常量使用 UPPER_SNAKE_CASE
2. 检查错误处理：所有异步操作必须有 try-catch
3. 检查安全性：不允许拼接 SQL，必须使用参数化查询
4. 检查性能：避免在循环中做 IO 操作

## 审查重点
{{review_focus}}

## 输出格式
- 问题等级：🔴严重 / 🟡警告 / 🔵建议
- 问题位置：文件名:行号
- 问题描述
- 修复建议
```

5. 定义字段（可选）：

| fieldId | label | type | token |
|---------|-------|------|-------|
| review_focus | 审查重点 | textarea | `{{review_focus}}` |

6. 保存并启用

### 4.3 版本管理

- **创建版本**：在修改提示词前，点击 "创建版本" 保存当前状态快照
- **回滚版本**：如果修改后效果不佳，选择历史版本点击 "回滚" 恢复
- 版本号自动递增（v1.0 → v2.0 → v3.0）

### 4.4 启用/禁用

- 启用的技能会在签出容器时注入到开发环境中
- 禁用的技能不会注入容器，但配置保留不丢失
- 可以随时切换启用状态

## 5. 技能注入流程

技能通过以下流程从配置到最终生效：

```
┌─────────────┐     ┌──────────────┐     ┌──────────────┐
│  管理员配置    │     │  签出时注入    │     │  对话时激活    │
│  Skill 管理页 │ ──→ │  容器创建流程  │ ──→ │  AI Chat 面板 │
└─────────────┘     └──────────────┘     └──────────────┘
```

### 5.1 签出时注入（自动）

用户签出程序时，系统自动执行以下步骤：

1. 创建容器
2. 注入 SSH 密钥
3. 克隆代码
4. 加载依赖
5. **注入技能** ← 在此步骤执行
6. 健康检查
7. 环境就绪

注入过程：
- 查询数据库中所有 `enabled = true` 的技能
- 序列化为 JSON 格式
- 通过 AI Proxy 的 `POST /api/skills/register` 接口写入容器
- 技能数据存储在容器的 `/skills/skills.json` 文件中

### 5.2 对话时激活（手动选择）

1. 用户在 IDE 右下角打开 AI Chat 面板
2. 在输入框上方可以看到已注入的技能列表
3. 点击勾选要激活的技能
4. 发送消息时，选中的技能 ID 随请求一起发送
5. 容器 AI Proxy 读取技能文件，提取选中技能的提示词
6. 将提示词注入 AI 系统提示词的 "Active Skills" 部分
7. AI 按照激活的技能指令进行响应

## 6. 触发方式

### 6.1 聊天激活

在 AI Chat 面板中选择技能后发送消息，AI 的回复将结合技能提示词。

```
用户消息: 帮我审查这个函数的代码质量
激活技能: [代码审查助手]

→ AI 将按照"代码审查助手"中定义的审查规则和输出格式进行审查
```

### 6.2 系统提示词构建

容器收到聊天请求后，构建系统提示词的结构：

```
## Page Code
（当前工作区文件内容）

## Dependencies
（已加载的依赖库内容）

## Active Skills
（用户选中的技能提示词）
```

AI 模型接收到完整的系统提示词后，会同时参考代码上下文、依赖信息和技能指令来生成回复。

### 6.3 使用统计

- 每次 AI 回复后，系统自动检测回复中是否引用了激活的技能
- 如果检测到使用，自动调用 `POST /api/skills/{id}/use` 递增使用计数
- 同一会话中同一技能只计数一次（去重机制）
- 使用次数在技能列表中显示，高频使用的技能排在前面

## 7. API 接口

### 7.1 技能 CRUD

| 方法 | 路径 | 说明 | 权限 |
|------|------|------|------|
| GET | /api/skills | 获取技能列表（可按 enabled 过滤） | 所有用户 |
| POST | /api/skills | 创建技能 | 管理员 |
| PUT | /api/skills/{id} | 更新技能 | 管理员 |
| DELETE | /api/skills/{id} | 删除技能 | 管理员 |

### 7.2 使用统计

| 方法 | 路径 | 说明 | 权限 |
|------|------|------|------|
| POST | /api/skills/{id}/use | 记录使用（含去重） | 所有用户 |

**请求体**：
```json
{ "sessionId": "会话ID" }
```

### 7.3 版本管理

| 方法 | 路径 | 说明 | 权限 |
|------|------|------|------|
| GET | /api/skills/{id}/versions | 获取版本列表 | 所有用户 |
| POST | /api/skills/{id}/versions | 创建版本快照 | 管理员 |
| POST | /api/skills/{id}/rollback | 回滚到指定版本 | 管理员 |

**回滚请求体**：
```json
{ "versionId": "版本UUID" }
```

### 7.4 容器注册

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | /api/skills/register | 容器内注册技能（签出时自动调用） |

**请求体**：
```json
{
  "name": "技能名称",
  "prompt": "提示词内容"
}
```

## 8. 提示词编写指南

### 8.1 基本结构

```
角色定义（你是一个...）

## 规则/约束
1. 规则1
2. 规则2

## 输入说明
{{input_field}}  ← 模板变量，运行时替换为用户输入

## 输出格式
要求的输出格式说明
```

### 8.2 模板变量

使用 `{{fieldName}}` 语法定义模板变量，运行时由对应的 SkillField 输入值替换。

```
请分析以下 {{language}} 代码：
{{code_snippet}}

重点关注：{{focus_area}}
```

对应字段定义：

| fieldId | label | type | token |
|---------|-------|------|-------|
| language | 编程语言 | select (Java/JS/Python) | `{{language}}` |
| code_snippet | 代码片段 | textarea | `{{code_snippet}}` |
| focus_area | 关注点 | text | `{{focus_area}}` |

### 8.3 最佳实践

1. **明确角色**：开头明确 AI 的角色定位
2. **结构化规则**：用编号列表定义清晰的规则
3. **示例驱动**：提供输入输出示例帮助 AI 理解
4. **约束边界**：明确说明哪些事情不要做
5. **输出格式**：定义统一的输出格式（Markdown、JSON 等）
6. **迭代优化**：通过版本管理不断优化提示词效果
