# Feature Specification: Appsmith AI-IDE Web 开发平台

**Feature Branch**: `001-appsmith-ai-ide`
**Created**: 2026-03-24
**Status**: Draft
**Input**: 基于 AI-IDE.html 原型、AI_IDE_PRD V6.0 及技术文档 V5.0 综合提炼

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 开发者登录并签出 Page 进入 IDE（Priority: P1）

开发者打开平台，使用账号密码登录系统。登录成功后看到 Page 列表页，展示所有可开发的 Appsmith Page 卡片。开发者点击一个空闲的 Page 卡片（如 DashboardPage），进入该 Page 的 IDE 编辑页面。页面右上角显示「签出」按钮（Page 空闲状态），开发者可先以只读模式浏览代码。点击「签出」后，系统依次创建 Docker 容器、从内网 GitLab 克隆 dev 分支代码、加载依赖库、启动 AI 服务，全程以步骤动画展示进度。完成后页面重新加载，右上角按钮变为「签入」，开发者即可开始编码。

**Why this priority**: 登录与签出是使用平台的入口流程，无此功能则所有后续操作无法进行，是 MVP 的核心基础。

**Independent Test**: 可通过登录账号、点击 Page 卡片进入 IDE 编辑页面、点击右上角「签出」按钮触发签出流程、确认按钮变为「签入」且可正常编码来独立测试，交付价值为「开发者可安全进入隔离开发环境」。

**Acceptance Scenarios**:

1. **Given** 未登录用户访问任意页面，**When** 系统检测到无有效 Token，**Then** 自动重定向至登录页
2. **Given** 用户在登录页输入正确的账号密码，**When** 点击登录，**Then** 系统签发 Token 并跳转至 Page 列表页，显示用户信息
3. **Given** 用户在登录页输入错误密码，**When** 点击登录，**Then** 显示「账号或密码错误」提示，不跳转
4. **Given** 用户 Token 过期，**When** 发起任何请求，**Then** 返回 401 并自动跳转登录页，清除本地 Token
5. **Given** 用户已登录并查看 Page 列表，**When** Page 列表加载完成，**Then** 每张卡片显示名称、GitLab 仓库信息、dev 分支及状态标签（空闲/已签出/我的签出），点击任意卡片进入该 Page 的 IDE 编辑页面
6. **Given** 用户在 IDE 编辑页面点击右上角「签出」按钮，**When** 签出流程启动，**Then** 系统按步骤动画展示进度（锁定 → 创建容器 → git clone → 加载依赖库 → AI 启动 → 健康检查），全部完成后页面重新加载，右上角按钮变为「签入」，编辑器和 AI 对话功能解锁
7. **Given** 签出流程中容器启动超过 60 秒，**When** 超时触发，**Then** 系统自动回滚（停止容器、解除 Page 锁定），提示用户重试
8. **Given** Page 已被他人签出，**When** 另一用户点击该 Page 卡片进入 IDE 编辑页面，**Then** 右上角按钮显示为「已签出」，页面为只读模式（不可编辑、不可 AI 对话），并显示签出人信息
9. **Given** 用户 Token 已过期但存在 active 签出记录，**When** 用户重新登录，**Then** 系统签发新 Token 并关联原容器 ID，对容器执行健康检查（检查 Docker 容器运行状态 + 容器内 AI 服务心跳接口），健康检查通过后直接跳转该 Page 的 IDE 编辑页面，右上角按钮显示「签入」，无需用户确认
10. **Given** 用户点击一个未签出（空闲）的 Page 卡片，**When** IDE 编辑页面加载完成，**Then** 左侧文件树展示 dev 分支完整目录结构，支持折叠/展开，编辑器显示文件树第一个文件的内容，编辑器不可输入，AI 对话面板不可用，右上角显示「签出」按钮

### User Story 2 - 开发者在 IDE 中编写代码并与 AI 协作（Priority: P1）

开发者完成签出后，IDE 编辑页面进入可编辑状态（右上角按钮为「签入」）。左侧文件树展示当前 Page 的所有文件，点击文件切换编辑，中间编辑器支持语法高亮（JavaScript/JSON），底部 AI 对话面板可向 Claude AI 提问。AI 能感知当前 Page 仓库的完整代码和已加载的依赖库，给出带代码 Diff 的具体修改建议。开发者可点击「应用到代码」将建议写入编辑器，然后点击右上角「全部保存」按钮保存所有文件到容器本地。

**Why this priority**: 编码与 AI 协作是平台的核心使用场景，直接决定产品价值。

**Independent Test**: 签出 Page 后，在 IDE 编辑页面中打开文件编辑、通过 AI 对话获取建议并应用到代码来独立测试，交付价值为「开发者可借助 AI 高效编写 Appsmith Page 代码」。

**Acceptance Scenarios**:

1. **Given** 开发者进入 IDE 编辑页面（编辑模式），**When** 文件树加载完成，**Then** 仅展示当前签出 Page 的文件（canvas.json 和 JsObjects/ 目录下的 JS 文件），文件夹支持折叠/展开
2. **Given** 开发者点击文件树中的某个文件，**When** 文件打开，**Then** 编辑器显示该文件内容并带有语法高亮，顶部 Tab 栏新增该文件 Tab 并激活
3. **Given** 开发者在任意 Tab 中修改了编辑器中的代码，**When** 内容发生变化，**Then** 该 Tab 上显示「未保存」标记，顶部「全部保存」按钮激活
4. **Given** 开发者点击「全部保存」按钮，**When** 保存操作完成，**Then** 所有已修改 Tab 的文件内容批量写入容器本地文件系统，所有 Tab 的「未保存」标记同时清除，「全部保存」按钮变为不可用状态
5. **Given** 开发者在 AI 对话区输入问题（如「给 fetchData 函数添加错误处理」），**When** 发送消息，**Then** AI 以 SSE 流式返回回复，包含 Markdown 格式文本和代码 Diff 建议
6. **Given** AI 返回了代码建议并在编辑器上方显示 Diff 提示条，**When** 开发者点击「应用修改」，**Then** 建议的代码变更写入编辑器，文件标记为「已修改」
7. **Given** 开发者点击「忽略」，**When** 操作完成，**Then** Diff 提示条关闭，编辑器保持原始代码
8. **Given** 开发者在对话面板输入区按 Enter 键，**When** 消息发送，**Then** 消息立即出现在对话区并右对齐，AI 回复左对齐显示，支持 Markdown 渲染

### User Story 3 - 开发者签入代码提交到 GitLab（Priority: P1）

开发者完成代码修改后，点击右上角「签入」按钮。若存在未保存文件，系统提示是否在签入前保存；处理完保存选择后，弹出 commit message 输入框（必填，不超过 200 字符）。确认后系统在容器内执行 git add、git commit 和 git push，将代码推送到内网 GitLab 对应仓库的 dev 分支。推送成功后，系统销毁 Docker 容器，解除 Page 锁定，页面刷新，右上角按钮恢复为「签出」。

**Why this priority**: 签入是开发流程的闭环，确保代码变更安全持久化到远程仓库，是 MVP 必备环节。

**Independent Test**: 签出 Page 后修改文件并执行签入操作，验证代码成功推送到 GitLab 且 Page 恢复空闲状态。

**Acceptance Scenarios**:

1. **Given** 开发者点击右上角「签入」按钮且不存在未保存文件，**When** 签入按钮被点击，**Then** 系统直接弹出 commit message 输入框（必填，不超过 200 字符）
2. **Given** 用户确认签入，**When** 签入流程执行，**Then** 容器内依次执行 git add、git commit、git push origin dev，代码推送至 GitLab
3. **Given** git push 成功，**When** 推送完成，**Then** 系统销毁容器、解除 Page 签出锁定、状态恢复「空闲」，刷新当前 IDE 编辑页面，右上角按钮恢复为「签出」
4. **Given** git push 因权限问题或远程仓库拒绝等非冲突原因失败，**When** 推送失败，**Then** 提示用户具体错误信息，容器保留，签入按钮保持可用，用户可确认问题后重试签入
5. **Given** git push 出现无法自动解决的冲突，**When** 推送失败，**Then** 提示用户「代码冲突无法自动解决，请联系管理员或通过 GitLab 界面手动处理后重试签入」，容器保留，签入按钮保持可用
6. **Given** 开发者点击右上角「签入」按钮且存在未保存文件（Tab 上有「未保存」标记），**When** 签入按钮被点击，**Then** 系统弹出提示「存在未保存的文件，是否在签入前保存？」，点击「是」执行全部保存后继续签入流程；点击「否」弹出二次确认弹窗「未保存的改动将永久丢失，确认继续签入？」，用户点击「确认」后跳过保存直接进入签入流程，点击「取消」则返回编辑状态，签入流程中断

### User Story 4 - 开发者选择和切换 AI Skill（Priority: P2）

开发者在 IDE 对话区点击「Skills」按钮，打开 Skill 选择抽屉。抽屉从右侧滑入，展示可用的 Skill 列表（支持搜索和标签筛选）。开发者可多选启用 Skill（如「错误处理模板」和「代码审查」），确认后 AI 在后续对话中融入所选 Skill 的 Prompt 模板，增强特定场景下的 AI 能力。

**Why this priority**: Skill 系统是 AI 能力增强的关键差异化功能，显著提升开发效率，但非最基础的编码功能。

**Independent Test**: 进入 IDE 编辑页面后打开 Skill 抽屉、选择 Skill 并发送对话，验证 AI 回复体现了所选 Skill 的能力。

**Acceptance Scenarios**:

1. **Given** 开发者在 IDE 编辑页面中点击对话区头部的「Skills」按钮，**When** 按钮被点击，**Then** Skill 选择抽屉从右侧滑入，展示可用 Skill 列表，按使用次数降序排列
2. **Given** 开发者在 Skill 搜索框输入关键字，**When** 输入内容变化，**Then** 列表实时过滤显示匹配的 Skill
3. **Given** 开发者点击标签 Chip 进行筛选，**When** 标签被选中，**Then** 列表只显示包含该标签的 Skill
4. **Given** 开发者勾选多个 Skill，**When** 点击「确认并应用」，**Then** 抽屉关闭，对话区头部上下文标签栏更新显示激活的 Skill（紫色标签），AI 后续回复融入所选 Skill 的 Prompt
5. **Given** 开发者在对话过程中重新打开 Skill 抽屉修改选择，**When** 确认新选择，**Then** AI 立即使用更新后的 Skill 组合，不中断当前会话

### User Story 5 - 管理员配置和更新依赖库（Priority: P2）

管理员进入依赖库管理页面，以卡片形式查看所有已配置的依赖库（显示命名空间、描述、URL、版本、加载状态、接口预览）。管理员可添加新依赖库、删除现有依赖库、或触发单个/全部更新。更新后容器重新拉取最新库代码，AI 上下文自动刷新，后续对话使用最新接口。

**Why this priority**: 依赖库管理使 AI 能感知最新的外部库接口，是保证 AI 辅助代码准确性的重要功能。

**Independent Test**: 在依赖库管理页面添加一个新依赖库并更新，验证 AI 在对话中能正确理解该库的接口。

**Acceptance Scenarios**:

1. **Given** 管理员进入依赖库管理页，**When** 页面加载完成，**Then** 以卡片形式展示所有已配置的依赖库，每张卡片包含命名空间、描述、URL、版本、加载状态、接口代码预览
2. **Given** 管理员点击「添加依赖库」，**When** 弹窗出现，**Then** 表单包含库名（命名空间）、代码 URL、版本备注、描述字段，库名和 URL 为必填
3. **Given** 管理员填写完整信息并提交，**When** 添加成功，**Then** 新依赖库卡片出现在列表中，状态为「已加载」，更新日志追加记录
4. **Given** 管理员点击某个依赖库卡片的「更新」按钮，**When** 更新流程执行，**Then** 后端重新从 URL 拉取最新依赖库代码，所有当前 active 签出的开发者的 AI 上下文在其下一条消息发送时自动使用新依赖库，这些开发者的对话区各自显示系统消息「依赖库已更新，后续对话将使用最新接口」
5. **Given** 管理员点击「全部更新」，**When** 更新完成，**Then** 所有依赖库代码重新拉取，所有当前 active 签出的开发者的 AI 上下文在各自下一条消息时使用最新依赖库，更新日志记录本次批量更新

---

### User Story 6 - 管理员管理 Skill 配置（Priority: P2）

管理员进入 Skill 配置页面，查看分区展示的已启用和可用 Skill 列表。管理员可新建 Skill（填写名称、描述、标签、Prompt 模板、参数）、编辑现有 Skill、启用/禁用 Skill、以及进行版本迭代。Skill 列表按使用次数降序排列。

**Why this priority**: Skill 管理是平台可扩展性的保障，管理员需要灵活配置 AI 能力模块以适应不同开发场景。

**Independent Test**: 在 Skill 配置页创建新 Skill、编辑 Prompt 并启用，验证在 IDE 编辑页面中该 Skill 可被选择使用。

**Acceptance Scenarios**:

1. **Given** 管理员进入 Skill 配置页，**When** 页面加载完成，**Then** 分两区展示已启用 Skill 和可用 Skill，列表按使用次数降序排列
2. **Given** 管理员点击「新建 Skill」，**When** 填写名称、描述、标签、Prompt 模板并提交，**Then** 新 Skill 出现在可用列表中
3. **Given** 管理员切换 Skill 的启用/禁用开关，**When** 状态切换，**Then** 卡片在两个分区间移动，计数实时更新
4. **Given** 管理员编辑 Skill 的 Prompt 模板并保存，**When** 选择「创建新版本」，**Then** 版本号递增，历史版本保留可回滚
5. **Given** Skill 被开发者在对话中使用，**When** AI 在本次会话中实际引用该 Skill 的 Prompt 模板生成回复，**Then** 该 Skill 的使用次数在本次会话内 +1（同一会话内多次引用不重复计数），列表排序实时更新

### User Story 7 - 管理员进行系统配置（Priority: P3）

管理员进入系统配置页面，配置容器资源限制（内存上限、CPU 上限、最大并发容器数）、Claude 工具黑白名单、SSH Key 管理和其他系统参数。配置修改仅影响之后新建的容器。

**Why this priority**: 系统配置是平台运维的保障功能，确保资源可控和安全策略落地，但不影响核心开发流程。

**Independent Test**: 在系统配置页修改容器内存上限参数，签出新 Page 验证容器使用了新配置值。

**Acceptance Scenarios**:

1. **Given** 管理员进入系统配置页，**When** 页面加载完成，**Then** 展示容器资源限制、Claude 工具黑白名单、SSH Key 管理、JWT 有效期等配置项
2. **Given** 管理员修改容器内存上限为 2 GB，**When** 保存配置，**Then** 修改立即生效并持久化到数据库，之后新建的容器使用 2 GB 内存上限
3. **Given** 管理员在工具黑白名单中禁用 Bash 工具，**When** 保存后签出新 Page，**Then** 新容器中 AI 无法使用 Bash 工具
4. **Given** 管理员上传 SSH 私钥并填写 GitLab 域名，**When** 点击「测试连接」，**Then** 系统验证 SSH Key 可访问 GitLab 并返回测试结果
5. **Given** 已有容器正在运行，**When** 管理员修改系统配置，**Then** 已运行容器不受影响，仅后续新建容器使用新配置

---

### User Story 8 - 多人并行开发不同 Page（Priority: P2）

多个开发者可同时签出不同的 Page，各自在独立的 Docker 容器中工作。每个 Page 拥有独立的 GitLab 仓库，签出锁保证同一时刻只有一个用户操作某个 Page，不会产生 Git 冲突。

**Why this priority**: 并行开发是团队协作的基础需求，确保多人可高效同时工作而不互相干扰。

**Independent Test**: 两个用户分别签出不同的 Page，各自独立编码和签入，验证两人工作互不影响。

**Acceptance Scenarios**:

1. **Given** 开发者 A 签出 DashboardPage，**When** 开发者 B 查看 Page 列表，**Then** DashboardPage 显示「已签出」状态和签出人（开发者 A），操作按钮禁用
2. **Given** 开发者 A 已签出 DashboardPage，**When** 开发者 B 签出 UserPage，**Then** 系统成功创建独立容器，B 可正常进入 IDE 编辑页面编码
3. **Given** 两个开发者分别在各自容器中编码，**When** 各自签入，**Then** 代码分别推送到各自 GitLab 仓库的 dev 分支，互不干扰
4. **Given** 并发签出数达到系统配置的最大容器数上限，**When** 新用户尝试签出，**Then** 系统拒绝请求并提示「当前容器数已达上限，请等待其他开发者签入后重试」

---

### User Story 10 - 开发者通过快速调用面板触发 Skill 模板（Priority: P2）

开发者在 IDE 编辑页面的 Skill 面板中切换到「快速调用」标签页，查看所有已启用的 Skill 列表。无模板参数的 Skill 显示「直接触发」按钮，点击后立即将该 Skill 的 Prompt 注入 AI 上下文并发送，AI 结合当前 Page 完整代码上下文生成回复。含模板参数的 Skill 显示「填写并触发」按钮，点击后弹出模板参数填写表单 Modal，表单根据 Skill 配置的模板参数字段动态渲染（支持文本输入、多行文本、下拉选择、多选标签四种输入类型）。用户填写参数后，系统将参数值替换 Prompt 模板中的 `{{占位符}}`，生成最终 Prompt 并发送给 AI。

**Why this priority**: 快速调用和模板参数是 Skill 系统的核心增强功能，让开发者可以精准定制 AI 行为参数，显著提升 Skill 的实用性和灵活性。

**Independent Test**: 在 IDE 编辑页面打开 Skill 面板的「快速调用」标签页，点击一个含模板参数的 Skill 的「填写并触发」按钮，填写参数后提交，验证 AI 收到的 Prompt 中占位符已被替换为实际填写值。

**Acceptance Scenarios**:

1. **Given** 开发者在 IDE 编辑页面打开 Skill 面板，**When** 切换到「快速调用」标签页，**Then** 展示所有已启用 Skill 的列表，每个 Skill 显示名称、图标、描述，无模板参数的 Skill 显示「直接触发」按钮，含模板参数的 Skill 显示「填写并触发」按钮
2. **Given** 开发者点击无模板参数 Skill 的「直接触发」按钮，**When** 触发完成，**Then** 该 Skill 的 Prompt 注入 AI 上下文后发送，AI 结合当前 Page 完整代码上下文生成回复，对话区显示 AI 回复
3. **Given** 开发者点击含模板参数 Skill 的「填写并触发」按钮，**When** 按钮被点击，**Then** 弹出模板参数填写表单 Modal，表单标题显示 Skill 名称，根据该 Skill 配置的字段列表动态渲染输入控件（文本输入/多行文本/下拉选择/多选标签）
4. **Given** 用户在模板参数表单中填写参数，**When** 输入值变化，**Then** 表单顶部的 Prompt 预览区域实时更新，展示将 `{{占位符}}` 替换为实际填写值后的最终 Prompt
5. **Given** 用户完成参数填写并点击「生成提示词并发送」，**When** 提交成功，**Then** 系统将所有 `{{占位符}}` 替换为对应参数值，生成最终 Prompt 自动填入对话输入框（替换输入框原有内容），Modal 关闭，用户确认后点击发送按钮将 Prompt 发送给 AI
6. **Given** 用户在模板参数表单中点击「取消」，**When** 取消操作执行，**Then** Modal 关闭，不发送任何消息，编辑状态不变
7. **Given** 用户点击「生成提示词并发送」但存在未填写的必填参数，**When** 提交被拦截，**Then** 必填参数字段高亮提示「此项为必填」，表单不关闭，不发送消息
8. **Given** 开发者通过意图识别提示栏点击「填写参数」进入模板表单，**When** 表单提交成功，**Then** 生成的最终 Prompt 自动填入对话输入框并替换原有内容，用户可在发送前查看或修改，确认后点击发送按钮将 Prompt 发送给 AI；若用户点击「取消」关闭表单，则输入框保留原始输入内容不变

### User Story 11 - 系统自动识别用户输入并匹配 Skill 意图（Priority: P3）

开发者在 AI 对话输入框中输入内容时，系统根据已启用 Skill 的触发关键词列表，自动识别是否匹配某个含模板参数的 Skill。匹配成功后，在输入框上方显示意图识别提示栏，开发者可选择「填写参数」打开该 Skill 的模板表单，或点击 × 忽略提示。

**Why this priority**: 意图识别是 Skill 系统的智能增强，让开发者无需手动查找 Skill，输入时自动推荐，但不影响核心对话功能。

**Independent Test**: 在 AI 对话输入框中输入包含某个 Skill 触发关键词的文字，验证意图识别栏正确出现并显示匹配的 Skill 名称，点击「填写参数」后模板表单正确弹出。

**Acceptance Scenarios**:

1. **Given** 开发者在对话输入框中输入文字，**When** 输入停顿超过 300 毫秒（防抖），**Then** 系统根据所有已启用 Skill 的触发关键词列表进行匹配检测
2. **Given** 输入内容匹配到一个含模板参数的已启用 Skill，**When** 匹配成功，**Then** 输入框上方显示意图识别提示栏，内容为「识别到 Skill：{Skill名称} — 该 Skill 含模板参数」，提供「填写参数」按钮和 × 关闭按钮
3. **Given** 开发者点击意图识别栏的「填写参数」按钮，**When** 按钮被点击，**Then** 弹出该 Skill 的模板参数填写表单 Modal（行为与快速调用面板触发模板表单一致：表单标题显示 Skill 名称，根据字段列表动态渲染输入控件），输入框中已输入的文字保留
4. **Given** 开发者点击意图识别栏的 × 关闭按钮，**When** 关闭操作执行，**Then** 意图识别栏隐藏，当前输入内容不受影响，同一 Skill 在本次输入会话中不再重复提示
5. **Given** 开发者修改输入内容导致关键词变化，**When** 新内容匹配到不同的 Skill，**Then** 意图识别栏更新为新匹配的 Skill 信息
6. **Given** 输入内容匹配到一个无模板参数的已启用 Skill，**When** 匹配成功，**Then** 不显示意图识别栏（无模板 Skill 无需参数填写，直接通过 Skill 被激活后注入上下文生效，无需额外提示）

### Edge Cases

- 当 GitLab 不可用时签出/签入如何处理？签出失败回滚并提示用户；签入失败时容器保留，用户可等待 GitLab 恢复后重试
- 当依赖库 URL 不可达时如何处理？降级跳过加载，AI 标注上下文缺失，提示用户检查配置
- 当用户长时间不操作容器如何处理？容器保持运行直到用户主动签入或管理员手动清理
- 当 git clone 使用的 SSH Key 无效时如何处理？签出流程自动回滚，提示管理员检查 SSH Key 配置或 GitLab 连通性
- 当签入时 git push 出现冲突如何处理？提示用户「代码冲突无法自动解决，请联系管理员或通过 GitLab 界面手动处理后重试签入」，容器保留，签入按钮保持可用
- 当前端存储的 JWT Token 被篡改时如何处理？后端校验失败返回 401，前端清除 Token 并跳转登录页
- 当容器名额耗尽（运行中容器数达到系统配置上限）时，新签出请求被拒绝并提示用户；管理员可通过运维容器管理页面查看所有运行中容器并手动强制释放
- 当用户重新登录后容器健康检查失败时，提示用户「容器状态异常，原签出记录已失效」，解除 Page 锁定，用户需重新签出
- 当 Skill 模板参数填写表单提交时，若部分非必填参数未填写，如何处理 Prompt 中对应的 {{占位符}}？保留原始占位符文本原样注入，不做替换，AI 将收到含原始占位符的 Prompt
- 当意图识别同时匹配到多个已启用 Skill 时如何处理？优先显示使用次数最高的 Skill 的意图识别栏，一次只提示一个
- 当用户正在填写 Skill 模板参数表单时，若 SSE 连接中断，如何处理？表单保持打开状态，用户可重新点击「生成提示词并发送」重试

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 调用外部用户管理服务 API 完成账号密码验证，验证通过后由外部服务签发 JWT Token（默认有效期 8 小时）。登录时若检测到该账号已有 active session（其他设备已登录），则拒绝登录并提示「该账号已在其他设备登录，请先退出」。登录时若用户存在 active 签出记录，签发新 Token 并关联原容器 ID，登录后直接跳转该 Page 的 IDE 编辑页面。Token 过期且无 active 容器时，自动跳转登录页
- **FR-002**: 系统 MUST 对所有后端接口（登录除外）统一校验 JWT Token，Token 无效时返回 401 并跳转登录页。若用户存在 active 签出记录，每次有效请求自动延长 Token 有效期至当前时间 +8 小时（滑动续期）。Token 过期且无 active 容器时返回 401 并清除本地 Token
- **FR-003**: 系统 MUST 以卡片形式展示所有可开发的 Appsmith Page，每张卡片包含名称、GitLab 仓库信息、dev 分支、状态标签（空闲/已签出/我的签出）。点击任意卡片进入该 Page 的 IDE 编辑页面
- **FR-004**: 系统 MUST 支持 Page 关键字搜索和按状态过滤（全部/空闲/我的签出），无匹配结果时显示「未找到程序」
- **FR-005**: 系统 MUST 在签出时依次执行：锁定 Page → 创建 Docker 容器 → 注入 SSH Key → git clone dev 分支 → 加载依赖库 → 启动 AI → 健康检查，全程展示步骤动画。健康检查定义为：检查 Docker 容器运行状态正常 + 容器内 AI 服务心跳接口可正常访问（HTTP 200）
- **FR-006**: 系统 MUST 保证同一 Page 同一时刻只能被一个用户签出，已签出的 Page 对其他用户禁止操作
- **FR-007**: 系统 MUST 在签出超时（60 秒）时自动回滚，停止容器并解除 Page 锁定
- **FR-008**: 系统 MUST 提供 IDE 编辑页面，包含左侧文件树、中间代码编辑器、底部 AI 对话面板、右上角三态状态按钮（「签出」/「签入」/「已签出」）的布局。页面在只读模式下（按钮为「签出」或「已签出」）编辑器不可输入、AI 对话面板不可用；在编辑模式下（按钮为「签入」）全功能解锁
- **FR-009**: 文件树 MUST 根据当前页面模式展示文件列表，文件夹支持折叠/展开，点击文件切换编辑。只读模式下（按钮为「签出」或「已签出」），文件树数据来自 GitLab 代理接口（FR-030），展示 dev 分支完整目录结构；编辑模式下（按钮为「签入」），文件树数据来自本地容器文件系统，仅展示当前签出 Page 的文件
- **FR-010**: 代码编辑器 MUST 支持 JavaScript 和 JSON 语法高亮、多 Tab 管理、行号显示、Tab 键缩进（2 空格）
- **FR-011**: 系统 MUST 提供「全部保存」功能，将所有已修改 Tab 的文件内容批量写入容器本地文件系统，并同时清除所有 Tab 的「未保存」标记。不提供单文件保存功能
- **FR-012**: AI 对话 MUST 以 SSE 流式方式返回回复，支持 Markdown 渲染和代码块高亮。SSE 连接中断时，丢弃已返回的部分内容，在对话区显示错误提示，由用户手动重发消息
- **FR-013**: AI MUST 能感知当前 Page 完整仓库代码（以完整文件形式注入上下文，包含 canvas.json 及 JsObjects/ 下所有文件）、已加载依赖库代码和激活的 Skill Prompt。以上上下文在每次对话消息发送时重新注入；当用户切换至不同 Page 的 IDE 编辑页面时，原 Page 的上下文自动失效，加载新 Page 的上下文
- **FR-014**: AI 代码建议 MUST 以 Diff 格式展示，支持「应用到代码」和「忽略」操作
- **FR-015**: 签入 MUST 依次执行 git add、git commit、git push origin dev，推送到 GitLab 对应仓库
- **FR-016**: 签入成功后 MUST 销毁 Docker 容器、解除 Page 锁定、刷新当前 IDE 编辑页面，右上角按钮恢复为「签出」状态
- **FR-017**: 系统 MUST 提供 Skill 选择抽屉，支持搜索过滤、标签筛选、多选勾选，确认后更新 AI 上下文
- **FR-018**: Skill 列表 MUST 按使用次数降序排列。使用次数统计规则：AI 在生成回复时实际引用该 Skill 的 Prompt 模板则计为一次使用，每次会话最多计 +1 次，同一会话内多次引用不重复计数
- **FR-019**: 系统 MUST 提供 Skill 管理功能，包括新建、编辑（名称/描述/标签/Prompt/参数）、启用/禁用、版本迭代
- **FR-020**: 系统 MUST 提供依赖库管理功能，包括添加（命名空间+URL 必填）、删除、单个更新、全部更新
- **FR-021**: 依赖库更新后 MUST 自动刷新所有当前 active 签出用户的 AI 上下文，每位用户在其下一条消息发送时使用新依赖库上下文。各 active 签出用户的 IDE 对话区显示系统消息「依赖库已更新，后续对话将使用最新接口」。管理员执行更新操作本身不需要持有签出记录
- **FR-022**: 系统 MUST 提供系统配置页（仅管理员可访问），支持配置容器资源限制、Claude 工具黑白名单、SSH Key 管理
- **FR-023**: 用户角色分为开发者和管理员两种，角色信息由外部用户管理服务提供。管理员拥有 Skill 管理、依赖库管理、系统配置、容器运维等额外权限，开发者仅可访问 Page 签出、IDE 编辑页面功能
- **FR-024**: SSH Key MUST 以加密形式存储，容器创建时注入 tmpfs，容器销毁后自动清除，AI 无法读取密钥路径
- **FR-025**: 全局状态栏 MUST 在所有页面底部常驻显示，IDE 编辑页面时展示文件名/分支/行列号/语言/编码/改动数，其他页面展示当前登录用户名
- **FR-026**: 系统 MUST 提供主导航入口，开发者可见：Page 签出、IDE 工作区（即 IDE 编辑页面）；管理员额外可见：依赖库管理、Skill 配置、容器运维。容器运维入口仅管理员角色可访问，对应 FR-031 的容器运维管理功能

> **注**：FR-027、FR-028、FR-029 已废弃，原只读视图功能已整合至 FR-008（IDE 编辑页面三态布局）和 FR-033（三态按钮行为定义），FR-030 起编号连续。

- **FR-030**: 系统 MUST 提供以下两个后端 GitLab 代理接口：
  - `GET /api/pages/{pageId}/tree`：返回指定 Page dev 分支目录结构
  - `GET /api/pages/{pageId}/files?path={filePath}`：返回指定文件内容
  接口响应格式见 API Schema 章节

- **FR-031**: 系统 MUST 提供容器运维管理功能（仅管理员可访问），展示所有运行中容器的列表（签出人、签出时长、Page 名称、容器状态）。管理员可对任意容器执行以下操作： （1）强制签入：将容器内已保存到文件系统的代码以系统自动生成的 commit message（格式：「[Admin Force Checkin] {Page名称} {操作时间}」）提交并推送到 GitLab dev 分支，推送成功后销毁容器并解除 Page 锁定； （2）强制销毁：不提交任何代码，直接销毁容器并解除 Page 锁定，容器内所有未签入的改动永久丢失，操作前需二次确认弹窗。强制签入失败处理：若 git push 推送失败（如 GitLab 不可达），容器保留，Page 锁定不解除，管理员可在容器运维页面重试强制签入操作

- **FR-032**: User Story 6 Scenario 4 中 Skill 版本回滚后，正在进行中的对话 MUST 继续使用回滚前的旧版本 Prompt 直至会话结束；新开启的对话使用回滚后的版本

- **FR-033**: 系统 MUST 在 IDE 编辑页面右上角提供三态状态按钮，按钮文案和行为根据当前 Page 状态动态切换：（1）「已签出」：Page 已被他人签出，点击刷新当前 Page 状态；（2）「签出」：Page 空闲，点击触发签出流程（锁定 → 创建容器 → clone 代码 → 加载依赖库 → 启动 AI → 健康检查），完成后页面重新加载，按钮变为「签入」；（3）「签入」：当前用户已签出，点击触发签入流程（未保存检查 → commit message 输入 → git push → 销毁容器），完成后页面刷新，按钮变为「签出」

- **FR-034**: 签入流程 MUST 在执行前检查是否存在未保存文件。若存在，弹出提示「存在未保存的文件，是否在签入前保存？」；用户选择「是」则执行全部保存后继续签入流程；用户选择「否」则弹出二次确认弹窗「未保存的改动将永久丢失，确认继续签入？」，用户点击「确认」后跳过保存直接进入签入流程，点击「取消」则返回编辑状态，签入流程中断

- **FR-035**: 每个 Skill MUST 支持定义模板参数字段列表（fields）。每个字段包含：字段 ID（唯一标识）、显示标签（label）、输入类型（type，支持 text 文本输入 / textarea 多行文本 / select 下拉选择 / chips 多选标签）、是否必填（required）、占位文本（placeholder）、可选项列表（options，仅 select 和 chips 类型需要）、对应 Prompt 占位符名称（token，与 Prompt 中的 `{{占位符}}` 对应）。无 fields 定义的 Skill 为无模板 Skill

- **FR-036**: FR-017 中的 Skill 面板（抽屉）MUST 在「选择 Skill」标签页之外提供第二个「快速调用」标签页，两者并列显示于同一抽屉内。「快速调用」标签页展示所有已启用 Skill 的列表。无模板参数的 Skill 显示「直接触发」按钮，点击后直接将 Prompt 注入 AI 上下文并发送；含模板参数的 Skill 显示「填写并触发」按钮，点击后弹出模板参数填写表单 Modal

- **FR-037**: 模板参数填写表单 Modal MUST 根据 Skill 的 fields 配置动态渲染输入控件，顶部显示 Prompt 实时预览（随用户输入实时替换 `{{占位符}}`）。提交时 MUST 校验所有必填字段已填写，未填写的必填字段高亮提示。非必填字段未填写时，Prompt 中对应的 `{{占位符}}` 保留原样不替换。提交成功后生成最终 Prompt，自动填入对话输入框（替换原有内容），Modal 关闭，用户确认后点击发送按钮将 Prompt 发送给 AI

- **FR-038**: 系统 MUST 在用户输入对话内容时进行意图识别：输入停顿 300 毫秒后（防抖），根据所有管理员已启用的 Skill（无论开发者是否在当前会话中勾选激活）的触发关键词列表匹配输入内容。仅当匹配到含模板参数的 Skill 时，在输入框上方显示意图识别提示栏（显示 Skill 名称和「填写参数」按钮）。同时匹配多个 Skill 时优先显示使用次数最高的。用户点击 × 忽略后，同一 Skill 在本次输入会话中不再重复提示

- **FR-039**: Skill 管理页的编辑抽屉 MUST 提供「模板参数」标签页，管理员可在此标签页中添加、编辑、删除模板参数字段。参数字段的 token 名称需与「系统 Prompt」标签页中的 `{{占位符}}` 对应，编辑器自动检测并高亮 Prompt 中已使用的占位符

### Key Entities

- **用户（User）**: 平台使用者。用户身份信息（用户名、密码、角色）由外部用户管理服务维护，本项目通过 API 获取。本项目本地存储的用户字段包含：外部服务用户 ID（用于关联）、显示名称（从外部服务同步）、角色缓存（开发者/管理员，从外部服务同步）、上次使用的 Skill 列表
- **Page**: Appsmith 页面开发单元，对应 GitLab 上的一个独立仓库，包含字段：Page 标识符、显示名称、GitLab 仓库 URL、默认分支（dev）、文件结构（canvas.json 和 JsObjects/ 目录）
- **签出记录（Checkout）**: Page 的签出状态记录，包含 Page 标识、签出人、容器 ID、AI 会话 ID、状态（active/checkedin/failed）。active：签出成功、容器运行中；checkedin：已签入、容器已销毁；failed：签出或签入流程异常回滚、Page 锁定已解除
- **Skill**: AI 能力模块，包含名称、描述、标签、Prompt 模板、触发关键词列表、模板参数字段列表（fields，每个字段含：字段 ID、显示标签、输入类型、是否必填、占位文本、可选项、对应 Prompt 占位符名称）、版本号、使用次数、启用状态。无模板参数字段的 Skill 触发时直接注入 Prompt；有模板参数字段的 Skill 触发时引导用户填写参数
- **依赖库（Dependency）**: 外部 JavaScript 库配置，包含命名空间、URL、版本、描述、加载状态
- **系统配置（SystemConfig）**: 平台级配置项键值对，包含容器资源限制、工具黑白名单、SSH Key 信息、JWT 有效期等
- **Docker 容器**: 每次签出创建的隔离开发环境，内含 AI 代理服务和文件管理服务，容器销毁后代码和密钥随之清除

## API Schema

### GET /api/pages/{pageId}/tree

请求参数：`pageId`（路径参数，Page 标识符）

成功响应（200）：

```json
{
  "pageId": "dashboard-page",
  "branch": "dev",
  "tree": [
    {
      "type": "file",
      "name": "canvas.json",
      "path": "canvas.json"
    },
    {
      "type": "directory",
      "name": "JsObjects",
      "path": "JsObjects",
      "children": [
        {
          "type": "file",
          "name": "COMMON.js",
          "path": "JsObjects/COMMON.js"
        },
        {
          "type": "file",
          "name": "PROCESS.js",
          "path": "JsObjects/PROCESS.js"
        }
      ]
    }
  ]
}
```

### GET /api/pages/{pageId}/files?path={filePath}

请求参数：`pageId`（路径参数）、`path`（查询参数，文件相对路径）

成功响应（200）：

```json
{
  "pageId": "dashboard-page",
  "filePath": "JsObjects/COMMON.js",
  "branch": "dev",
  "content": "// file content here",
  "encoding": "utf-8",
  "size": 1024
}
```

### 错误响应（统一格式，适用于以上两个接口）

```json
{
  "error": "GITLAB_UNREACHABLE",
  "message": "无法连接到 GitLab，请检查网络配置",
  "pageId": "dashboard-page"
}
```

可能的 error 值：
- `GITLAB_UNREACHABLE`：GitLab 不可访问
- `REPO_NOT_FOUND`：仓库不存在
- `FILE_NOT_FOUND`：指定文件不存在
- `PERMISSION_DENIED`：SSH Key 无权限访问该仓库

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 签出全流程（含创建容器、代码克隆、依赖加载、AI 启动）在 60 秒内完成，95% 的签出操作满足此要求
- **SC-002**: AI 对话响应（从用户发送到首字节返回）在 15 秒以内，95% 的对话满足此要求
- **SC-003**: IDE 编辑页面编辑模式下的文件读写操作（打开、保存）在 500 毫秒内完成，95% 的操作满足此要求。只读模式下的文件加载（需经过 GitLab 代理接口）在 2 秒内完成，95% 的操作满足此要求
- **SC-004**: 平台支持至少 20 个用户同时签出不同 Page 并行工作，互不干扰
- **SC-005**: 开发者能在 3 分钟内完成从登录到进入 IDE 开始编码的全流程（含登录约 30 秒 + 选择 Page 并点击「签出」约 30 秒 + 签出流程等待最长 60 秒 + 页面加载约 10 秒）
- **SC-006**: AI 对话能正确理解并引用当前 Page 仓库代码和依赖库接口，用户点击「应用修改」按钮的比率 ≥ 60%
- **SC-007**: 依赖库单个更新操作在 10 秒内完成，更新后 AI 在后续对话中能感知最新接口
- **SC-008**: 签入操作成功率达到 99%（排除 GitLab 不可用等外部因素），代码正确推送至 GitLab dev 分支
- **SC-009**: 所有 SSH Key 和 API Key 不在前端网络请求中暴露，容器销毁后密钥文件不残留
- **SC-010**: 平台在工作时间内可用率达到 99.5%

## Assumptions

- 内网 GitLab 已部署且可用，每个 Appsmith Page 已在 GitLab 上创建独立仓库并有 dev 分支
- 已获取有效的 Anthropic Claude API Key
- 部署环境具备运行 Docker 容器的能力，且已安装 Docker
- 管理员已配置有效的 SSH Key 用于访问内网 GitLab
- Appsmith Page 代码结构固定为 canvas.json + JsObjects/（COMMON.js、PROCESS.js 等）
- 单个 Page 仓库代码量在 AI Token 限制范围内，AI 上下文以完整文件形式注入，不使用分块加载策略
- 依赖库以 JavaScript 文件形式通过 URL 提供，且 URL 在内网可访问
- 用户账号、登录鉴权、角色信息（开发者/管理员）均由外部用户管理服务统一管理，本项目通过 API 集成，不自行开发登录模块，不提供用户创建和注册功能；开发者和管理员账号均在外部用户管理服务中配置
- WebFetch 和 WebSearch 工具在内网环境中默认禁用
- 对话历史由服务端管理，前端无需传递历史消息
